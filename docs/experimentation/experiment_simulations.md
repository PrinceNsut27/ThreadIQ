# ThreadIQ — A/B Experiment Simulation Methodology

> **Important — simulated results only:** This document describes the experiment simulator in `src/threadiq/experimentation/simulation.py`. It does not report a real online experiment, a production rollout, or causal evidence about actual customers. The cohorts are generated from configured probabilities and a seeded pseudo-random number generator.

## 1. What the simulator currently runs

The `run_benchmark_experiments()` method creates three independent binary-outcome demonstrations:

| ID | Initiative | Control sample | Treatment sample | Control probability | Configured relative treatment change |
|---|---|---:|---:|---:|---:|
| EXP-01 | Fit & sizing intelligence | 1,500 | 1,500 | 23.20% | -35% |
| EXP-02 | Express checkout | 2,000 | 2,000 | 10.98% | +65% |
| EXP-03 | Semantic search | 1,200 | 1,200 | 14.04% | +120% |

Treatment probability is calculated as `clip(p_control * (1 + relative_lift), 0.0001, 0.9999)`. Observed sample rates, confidence intervals, z-statistics and p-values are generated at runtime from Bernoulli draws. They are reproducible for a fixed code version, sample configuration and seed, but should not be copied from a different run.

## 2. Statistical method

- Binary outcomes use the two-proportion z-test implemented in `src/threadiq/experimentation/calculator.py`.
- Continuous outcomes can use the independent-samples Welch t-test.
- Sample-size and power calculations are planning utilities; a significant simulated result does not prove an intervention will work in production.
- Simulator outputs carry `source_type = 'simulated_experiment'`.

## 3. Decision policy

The benchmark simulator demonstrates methodology. Do not interpret its output as an instruction to ship a feature. A real product decision requires:

1. A pre-registered hypothesis and primary metric.
2. A justified randomization unit and eligibility definition.
3. A sample-size calculation based on a defensible baseline and minimum detectable effect.
4. Guardrail metrics such as revenue per visitor, cancellations, returns, latency and customer complaints.
5. SRM and instrumentation checks.
6. A live randomized experiment with adequate duration and representative traffic.
7. A rollout decision based on observed results, confidence intervals, guardrails and operational readiness.

Recommended portfolio language: **“The simulated cohort demonstrates the statistical testing workflow; validate the hypothesis with a controlled live experiment before rollout.”**

## 4. Reproduction

Run the project tests and launch the dashboard using the commands in the root README. Read benchmark outputs from the simulator result object or dashboard generated by the current checkout, rather than copying manually maintained figures from an earlier run.
